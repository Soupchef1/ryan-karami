    Programmable SPI Master

    TeamSiliconJackets
    ToolsSystemVerilog, RTL, Spec writing, Testbench
    LinksGitHub repository

    A memory-mapped SPI master that lets a RISC-V CPU talk to off-chip devices. Software queues words in a transmit FIFO, the hardware handles the serial protocol, and received words come back through a receive FIFO. I wrote the spec, the RTL and the sanity testbench before handing the design to the DV team.

    The Problem

    SiliconJackets' RISC-V chip needs to talk to devices off the chip, and SPI is the most common way to do that. Driving SPI pins directly from software (bit-banging) wastes CPU time and makes timing fragile. The chip needed a hardware SPI block that software sets up through registers and then leaves alone.

    Different devices expect different settings, so the block had to be configurable at runtime: clock polarity and phase, word size, bit order, clock speed and which chip select to use. It also had to stay safe when software does something wrong.

    The Process

    Spec first

    I wrote the specification before any RTL: six memory-mapped registers (CONFIG, CHIP_SELECT, TX_DATA, RX_DATA, STATUS and IRQ_ENABLE), every bit field and reset value, how a transfer should go, and a table of edge cases with what the hardware does in each one. That document became the contract with the CPU team and the DV team.

    Architecture

    The design has three parts. A register block decodes bus accesses and handles interrupts and chip selects. Two FIFOs, each 8 × 32-bit, buffer transmit and receive data. The spi_core contains the clock divider, the shift registers and a two-state IDLE/TRANSFER state machine. It supports all four SPI modes, 4-, 8-, 16- and 32-bit words, MSB- or LSB-first order, and a 16-bit clock divider.

    Designing for the software that uses it

    • Configuration shadowing: CONFIG changes take effect only between transfers, so a word is never sent with half-old, half-new settings.
    • Protected chip selects: software can't change the chip select or clock polarity mid-transfer. An illegal write is ignored and sets a sticky error flag.
    • No lost data: if the RX FIFO fills up, the core pauses instead of dropping received words.
    • Interrupts: one interrupt line with four maskable sources: error, data received, TX empty and transfer done.

    Optimization and testing

    After the first version worked, I optimized the RTL for area and cut it by 5%. A SystemVerilog testbench with an SPI slave model runs three directed tests. The first sends 32-bit words in mode 1 and checks both directions. The second sends nine 8-bit words to push the FIFO past full. The third tries an illegal chip-select change mid-transfer and checks that the hardware ignores it, flags the error, raises the interrupt and still finishes the word correctly.

    The Outcome

    The peripheral passes all of its directed checks and is going into SiliconJackets' third RISC-V core tapeout. The spec also lists the assertions the DV team should add, and it documents one known limitation for software: a clock-ratio setting of 0 or 1 hangs the core, so drivers must use 2 or more.
